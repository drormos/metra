# Metra: Cross-Platform Precision Metronome

## Overview
A sample-accurate metronome for Android and macOS, built with Flutter and `flutter_soloud`. Click timing comes from the C++ engine clock, so playback doesn't drift.

## Agreed behavior not in `docs/design/ui-spec.md`
Decisions made with the user that the spec doesn't state (or states differently). Keep them unless the spec is updated to say otherwise.
- **On-stage changes to a loaded song survive closing the app** (Revert / Save to song still shown after reopening).
- **Beat accent taps** are heard from the very next click (no waiting for a beat or bar).
- **Volume defaults:** Accent 100%, Beat 80%, Subdivision 45% (confirmed on the phone, 2026-10-15).
- **Visual offset:** default 0 ms (measured by eye on MacBook speakers; a USB-dongle headset needed ~20 ms); range −200 to +500 ms in 10 ms steps. The settings test uses the click if it's already playing and only stops what it started.
- **Tempo ruler acceleration:** besides the fling snapping, faster drags cover more bpm per pixel (up to 2.5×) while slow drags stay 1 bpm per 14 px. One swipe (drag plus coast) moves at most 135 bpm, so 30 → 300 takes two swipes.
- **Tempo ruler snapping:** short drags (under 5 bpm) and slow drags keep their exact value. A long, quick drag keeps it only if the finger rests on the value for 0.3 s first (a firmer haptic tick); otherwise lifting slides to the next multiple of 5 in the direction of movement. The tempo moves by 1 during the drag. A tap leaves the value alone.
- **Tap tempo:** registers on finger-down; averages the last 4 taps; ignores intervals more than 30% off the median; resets after 2 s; clamps to 30–300.
- **Setlist editor:** "Start with all songs" when creating a set (fills it A–Z).
- **Keyboard / foot pedals:** Space start/stop, T tap, ↑/↓ ±1, Shift+↑/↓ ±5, Page Down/→ next song, Page Up/← previous song (Bluetooth page-turner pedals; inside a setlist only).
- **Android:** plays alongside other music (no audio focus); stops when headphones are unplugged; Start/Stop and previous/next in the notification and lock screen; swiping the app away stops it.
- **iOS:** plays with the silent switch on and with the screen locked; mixes with other music. Lock-screen controls and headphone-unplug stop not built for iOS yet.
- **macOS:** opens as a phone-shaped, resizable window (~440×900).
- **Haptics** (spec "Haptics"): `Haptics.medium()` / `Haptics.tick()` in `lib/src/ui/haptics.dart` (`mediumImpact` / `lightImpact`; not `selectionClick`, which is Android's faint `CLOCK_TICK`). "Vibrate on touch" (`Library.vibrate`, default on, saved) gates every haptic via `Haptics.enabled` (synced in `main.dart`); it can only turn haptics off, the system setting still applies. Until the settings screen (Phase 6 step 2), the switch lives in the old settings sheet after Click sound. Not in the spec: the ruler's rest-to-lock gives a firmer `heavyImpact` (`Haptics.firm`); keyboard and pedal presses give none (haptics confirm touches). Built so far: Start/Stop, next/previous, choosing a song or set in the picker, long-press lift in the picker (medium); ±buttons (every step, tapped or held), Tap, ruler, beat blocks, subdivision button, time signature choice (light). Also: song editor edits and Preview, Save to song / Revert, time signature sheet (light; Preview medium).
- **Song editor Stop** (spec says only that leaving restores): Stop ends the preview immediately and the main screen's click resumes (or stays silent if it was stopped); Preview takes over again.
- **Names:** a new song's or set's default is "Song N" / "Setlist N" with the lowest number no current name uses (worked out each time; renaming frees a number). Two setlists, or two songs, can't share a name (ignoring case and surrounding spaces): Save is disabled with "Another setlist/song already has this name" (the user's call: a clear restriction beats a confusing library).
- **Ideas parked:** a "gap trainer" (play N bars, mute N bars) if wanted later.

## Phase 1: Core Engine & MVP Controls
**Goal:** Sample-accurate playback, decoupled architecture, verified timing. Each step ships with its own unit tests.

1. **Data Model & Grid Math (pure Dart):**
   - `MetronomePattern`: `beatsPerBar`, `stepsPerBeat`, and a list of steps (`accent` / `normal` / `silent`). Default: 4/4 quarters, accent on beat 1.
   - `BeatGrid`: step `n` time = `segmentAnchor + n * stepInterval`, computed in doubles (never accumulate rounded Durations).
   - A tempo change starts a new segment anchored at the last committed step, keeping the bar position.
2. **Audio Engine:**
   - Init `SoLoud` once in `main()` (try/catch, expose a failure state). Load accent and normal click WAVs (zero leading silence, checked by a test).
   - `ClickOutput` interface (`now`, `schedule`, `cancel`, `cancelAll`) with a SoLoud implementation using `getEngineTime` / `playScheduled` / `stop` / `stopAudioSource`.
   - `Scheduler`: a Dart Timer (~25 ms) schedules steps inside the lookahead window (~150 ms). Skip steps already past `now + guard`. Track pending handles.
   - While playing: `setAudioDeviceIdleTimeout(null)` and `await startAudioDevice()` before anchoring; restore on stop. Listen to `audioDeviceStartFailures`.
   - Scheduler tests run against a fake `ClickOutput`.
3. **State Controller:** `MetronomeController` (`ChangeNotifier`) for BPM (30–300, clamped), Play/Stop, and pattern.
   - Tempo change: cancel pending steps later than `now + guard`, re-anchor at the last committed step, continue the bar.
   - Stop: cancel the timer, `stopAudioSource`, clear handles. Start: anchor at `getEngineTime() + lead`, step 0.
   - Lifecycle: when the app is `hidden`/`inactive`/`paused`, extend the lookahead (~2 s) to survive timer throttling (macOS App Nap). Android background playback is not guaranteed until Phase 2.
4. **UI Shell:** High-contrast numeric BPM display, `±1` / `±10` buttons, Play/Stop, engine-failure message.
5. **Visual Sync:**
   - A `Ticker` reads `getEngineTime()` once per frame. Flash when engine time ≥ step time + visual offset.
   - The offset is signed and user-adjustable, default 0 ms (measured on MacBook speakers).
   - The engine clock advances in mix-buffer steps (~46 ms at 2048 frames). Extrapolate between clock updates with the Ticker's (monotonic) frame time so the flash lands on the right frame.
6. **Tap Tempo:** `Stopwatch` intervals from the last 4 taps. Drop intervals more than 30% off the median. Reset after 2 s idle. Clamp to 30–300. Apply through the controller's tempo-change path.
7. **Acceptance Test (Drift Check):** `integration_test/drift_test.dart` runs the real engine on macOS, captures the mixer output, and checks every click against the ideal grid (±2 samples).
   - Automated: 30, 60, 120 and 300 BPM (`--dart-define=DRIFT_SECONDS=300` for the 5-minute runs), a mid-bar tempo change, stop/start, and a 1 s isolate stall (stands in for App Nap).
   - Manual: headphones plugged and unplugged during playback, and the macOS app hidden for 60 s. **Not yet run; revisit before release.**
   - Run: `flutter test integration_test/drift_test.dart -d macos`.

### Engine Decisions
- `playScheduled` + `getEngineTime()`, not `playClocked` (no 2 s window, known engine time per step for visuals and tempo changes).
- Render-ahead ring off (`renderAheadFrames` unset). Scheduled clicks don't need low reactive latency; the visual offset is user-calibrated.
- `bufferSize` stays at the default 2048: scheduling is sample-accurate regardless, larger buffers avoid dropouts, and visual jitter is handled by extrapolation (Phase 1 step 5).
- Max active voices raised to 32 for headroom at fast subdivisions.
- Timing of changes while playing, chosen for responsiveness while staying on the pulse:
  - Beat accent taps: from the next click (`replaceLevels`).
  - Subdivision: from the next beat, bar position kept (`switchAtNextBeat`).
  - Time signature: the next beat starts a bar in the new meter (`switchAtNextBeat(restartBar: true)`).
  - Song switch: at the next bar line (`switchAtNextBar`), so a new song starts on beat 1.
  - ±BPM: at the next step.
- Decisions for the completed design: volume defaults Accent 100%, Beat 80%, Subdivision 45% (confirmed); the visual-offset test uses the playing click if there is one and only stops what it started; on-stage changes to a loaded song survive closing the app.
- Visual offset defaults to 0 ms (measured by eye on macOS: 0 ms on built-in speakers, 20 ms on a USB-dongle wireless headset), adjustable in the settings sheet from −200 to +500 ms in 10 ms steps to cover Bluetooth output. Not persisted until Phase 2.
- The drift check captures the mixer output rather than recording the speakers. The engine clock is paced by the output device, so the mix timeline is what plays; capture must use the engine's channel count (it does not convert channels).
- No audio focus on Android: focus would pause the user's music, and playing along with a track is a core use. Instead the click stops when a personal output (headphones, Bluetooth, USB audio) disappears, so it never jumps to the speaker. (audio_session's "becoming noisy" event only fires with focus, so this watches device removal.)
- No notification permission: the media card is a media-session notification, which Android 13+ exempts (ui-spec.md "Media controls"). It was requested at launch until the pre-release review.
- Audio device failures trigger one automatic `startAudioDevice()` retry; if it fails, the controller exposes the error for the UI.

## Phase 2: Persistence, Setlists & Mobile Background
**Goal:** Quick-access songs and setlists, reliable mobile playback.
1. **Background Audio:** Integrate `audio_service` so playback continues with the Android screen off or the app in the background. The refill loop must keep running in the background; use a long lookahead while backgrounded.
   - `MetronomeAudioHandler` mirrors the controller into audio_service: playing starts a `mediaPlayback` foreground service with Play/Stop in the notification and lock screen; swiping the app away stops.
   - Verified on a real Android phone (speaker): keeps playing on the lock screen, when minimized, and alongside other music; stops when the app is swiped away. Unplugging headphones stops the click.
   - `MainActivity` must extend `AudioServiceActivity`. A plain `FlutterActivity` makes audio_service start a second engine that runs `main()` again and re-initializes SoLoud.
2. **Persistence:** Simple JSON file storage for songs, setlists, and the visual latency offset.
   - One `library.json` in the app support folder (`LibraryStore`): written to a temp file then renamed, so a crash mid-save can't corrupt it; an unreadable file is kept aside as `library.json.corrupt-<time>` (renamed, or copied if renaming fails) and the app starts empty; a bad song or setlist is skipped rather than the whole file. A file from a newer app version, or one that can't be kept aside, is left untouched and the app runs without saving, saying why on the main screen. Failed saves show a notice until one works.
   - `LibraryController` owns songs and setlists (deleting a song removes it from setlists) and saves on every change.
   - Also restores the last session: tempo, pattern and flash offset.
3. **Setlist UI:** Side panel (macOS) or sheet (Android) for switching songs without stopping playback. A song switch applies tempo and pattern at the next bar boundary.
   - `LibraryPanel`: setlist picker (or all songs), tap a song to load it, save current settings as a song (added to the selected setlist), reorder by drag, rename, add/remove from setlists, delete with confirmation. The loaded song's name shows above the beat dots.
   - Next/previous song through the selected setlist (or all songs), stopping at the ends rather than wrapping: ◀ ▶ around the song name, Page Up/Down and ←/→ keys (Bluetooth page-turner pedals), and previous/next in the Android notification and lock screen.
   - Layout by width, not platform: from 800 px wide the panel sits beside the metronome; narrower windows open it as a sheet from the app bar.
4. **Expanded Patterns:** UI for 3/4, 6/8, 7/8 and subdivisions (eighths, triplets, sixteenths), mapped to the Phase 1 `MetronomePattern` model.
   - Time signatures 2/4, 3/4, 4/4, 5/4, 6/8, 7/8, 9/8, 12/8. In x/8 every eighth clicks and the BPM counts eighths; `beatUnit` is display-only.
   - Subdivisions 1–4 per beat, played as a new `soft` level (normal click at 40% volume) so the beat stays clear.
   - One dot per beat; tapping cycles normal → accent → silent, for groupings like 7/8 as 2+2+3. Changing the subdivision keeps custom accents; changing the time signature resets them. See the change-timing decision below.
   - Drift test covers triplets on the real engine.

## Phase 5x: Polyrhythm (done)
- Data: `MetronomePattern.polyrhythm` (0 = off, 2–7) and `polyStates` (accent / normal / silent per pulse, all regular when turned on), saved inside the pattern JSON (`polyrhythm`, `polyStates`), so songs, Free play's last pattern, and unsaved-change detection carry it with no extra plumbing. Older files load as off. `withBeats` turns it off when the new beat count equals it; `withPolyrhythm` refuses the beat count itself.
- Timing: pulse k sits `k × stepsPerBar ÷ n` steps into the bar (`pulseOffset`), timed with `BeatGrid.timeAt` (fractional steps, same doubles-then-round-once math as steps). The scheduler hands a pulse over together with the step it falls in, so pulses follow every existing rule: within the lookahead, never before now + guard, re-placed on tempo changes (including the tail of the last committed step), cut by a mid-bar meter switch, dropped by a song restart.
- While playing: turning it on or changing the number goes through `switchAtNextBeat` with the bar kept (from the next beat, the rest of that bar's pulses; was the next beat 1, which felt laggy on the phone); Off and cell taps go through `replaceLevels` (from the next pulse; Off silences at once). `applyEdit` (song editor, Revert) follows the same rules.
- Sound: `ClickOutput.schedulePulse`, the current click sound at `playScheduled(scale: 1.5)` (a fifth up; tune by ear): accented pulses on the accent sample at the Polyrhythm volume, regular ones on the normal sample at 75% of it. Muted pulses aren't scheduled. The voice-limit test now includes 7 pulses per bar.
- Lane (`PolyLane`): drawn over the top of the flexible space, 2px under the subdivision strip, so it takes no layout height. The empty space above the BPM never shrinks below the lane's height, so turning it on or off never moves the BPM. Cells are n equal parts of the bar width with 6px gaps, which is exactly placement by time (cell 1 under beat 1, the last ending with the last beat). Only the sounding cell lights, from its pulse to the next. Colors are new theme tokens (`pulseResting`, `pulseAccentResting`, `pulseMutedLine`).
- One visual clock: the beat blocks and the lane both read the frame timestamp (`SchedulerBinding.currentFrameTimeStamp`) instead of their own tickers' elapsed time, because they share one `EngineClockSmoother`; the visual offset applies to both.
- Time signature sheet: "Polyrhythm" row (Off · 2–7, Off slightly wider, beat count dimmed and disabled) with the plain-words hint. The meter button reads "4/4 · 3" when on.
- Volume: fourth slider "Polyrhythm", default 70%, in Reset.

The reorder applies when the finger lifts: `ReorderableList.onReorderEnd` saves the order and calls `cancelReorder()` at once, skipping Flutter's 250ms drop animation (which only applies the order at its end and swallows a new drag started meanwhile); `SettleIn` then slides the dropped row 150ms from where it was let go (measured from the proxy). A swipe past 40% applies on release, with no slide-out. Removal, rename re-sort and Undo have no animations, so nothing there can block.

The Setlists page (fallback) still sends a deleted loaded set to Free play.
- Long-press vs swipe (`swipe_row.dart`, values in `RowGestures`): a swipe is `SwipeGestureRecognizer`, a horizontal drag that accepts only past 32dp with |dx| ≥ 2×|dy| (reported from touch-down, with the first 32dp skipped so the row doesn't jump); long-press is `HoldGestureRecognizer` (400ms, tolerates 32dp; lifting earlier leaves the tap). In a set's songs the lift is `HoldToReorder`, the list's delayed drag with the same 400ms / 32dp; it puts the 32dp in a `MediaQuery` around itself because the list hands its recognizer the gesture settings found there. All three are ordinary arena members, so whichever crosses its threshold first owns the touch: a fired long-press shuts out the swipe, a started swipe shuts out the long-press, and the list's vertical scroll (normal 18dp slop) takes over first on vertical movement. `SwipeRow` replaces `Dismissible` (it can't take these thresholds) and does the 40% commit, the dialog-while-open, the slide out and the hint.

## Release builds
- Signing: `android/key.properties` (gitignored) → keystore `~/keys/metra-release.jks` (alias `metra`, PKCS12, RSA 4096, 10000 days). A copy of the properties sits next to the keystore. Losing the keystore means no updates to installed copies: back up `~/keys/`. Without `key.properties`, release builds fail (no silent debug signing).
- `keytool` isn't on the PATH (no system Java): use `/Applications/Android Studio.app/Contents/jbr/Contents/Home/bin/keytool`.
- **Every shared build bumps the build number** (`version: 1.0.0+N` in `pubspec.yaml`, the `+N`), so Android accepts it as an update and feedback emails name the exact build. Bump the version name (`1.0.0`) for user-visible releases.
- App ID `com.dror.metra` (was the template's `com.example.metra`; the Play Store refuses it and it can't change after sharing). Debug builds are `com.dror.metra.debug`, labelled "Metra dev" (`manifestPlaceholders["appLabel"]`), so they install beside the real app instead of over it. iOS/macOS bundle IDs follow.
- Play: `flutter build appbundle --release` → `build/app/outputs/bundle/release/app-release.aab`, signed with the same keystore, which is the upload key (Google Play app signing holds the final key).
- Build: `flutter build apk --release` → `build/app/outputs/flutter-apk/app-release.apk`. Install on the phone with `adb install -r` (keeps the library); `flutter install` uninstalls first and wipes it. `adb` is `~/Library/Android/sdk/platform-tools/adb`.
- Release builds log nothing (`debugPrint` is silenced in `main`).
